# New App Idea with Big Data Requirements

I am hashing out a new idea for an app that requires a sizable index of content. My app doesn't care about the complete index, only if users have activities related to their search. I thought it best to create a content type to reflect the shape of the data I need to index. Users can then search for this content and if I do not have the results, I can ask the user to submit an external search request and import the result. This will help me grow and scale our content based on user demand.

## Drupal Search and Fallback

There are two ways to approach Search with Drupal; Drupal Core Search and Drupal Search API. Drupal Core Search is a simple search engine that comes with Drupal. It is easy to set up and use, but it is not very powerful. Drupal Search API is a more powerful search engine that allows you to create custom search indexes and queries. It is more complex to set up and use, but it is much more powerful. It is also a requirement if you are working with plugins or modules. For my app purposes; I think I can get away with the core search since I am only indexing a single content type. My desired functionality fits in after the search process, so I can use the core search and then add my own fallback functionality. I will need to create a custom module to handle the fallback functionality. The module will need to implement hook_search_execute() to intercept the search query and check if there are any results. If there are no results, the module will need to prompt the user to submit an external search request. The module will also need to implement hook_search_index() to index the content type that I am using for my app.

## Cache and Indexing

The real cost of this approach is not the lone content type I am indexing. Instead, I need to breakout the fallback search and cache the results even if the user ends up not importing a result. This will help me avoid hitting the external search API too often and will also help me avoid hitting the external search API with the same query multiple times. I will need to create a custom table to store the cached results. The table will need to have a unique index on the search query and the external search API response. I will also need to implement a cron job to clean up the cached results that are older than a certain age.
